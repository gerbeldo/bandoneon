# Run parameters are player-set and persisted

The practice setup — game, session scope, items (scheduled or the first N of the introduction order), session size, daily cap, and spelling — is chosen on one screen and persisted in the settings blob, so tomorrow's run needs no setting up. This reverses two practice-memory decisions: session size (20) and daily cap (3) were "constants, not settings", and the scope was remembered for the browser session only. The reason is the player, who wants to quiz "the first 20 items" without waiting seven days for the daily ration and without tracking progress by hand. The old numbers stay as defaults, and the scheduler takes them as inputs, so it remains swappable. Fixed runs bypass the cap by construction — every item of the chosen range is asked once — rather than by setting a cap of infinity, which is why the session strip can honestly drop the "of 3" for them. Rejected: keeping the constants and adding a hidden developer switch (the need is the player's, daily), and one setup per game (one shared setup whose first field is the game is enough for one player).

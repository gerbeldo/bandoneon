# Prompt-driven recording seam with one grading engine

The session engine draws every prompt and therefore already holds the item key: it hands the game the key plus display data, and takes back only the raw answer (a named pitch or a tapped position) with elapsed time — no key, no grade. One midi-based rule grades every mode: exact sounding pitch is correct, same pitch class is partial credit, anything else is wrong. Rejected alternative: each game computing its own key and grade, which would reimplement memory rules per mode. Every mode this seam serves quizzes the button↔pitch correspondence, so future modes (direction-twin, chromatic-walk) plug in by rendering prompts and capturing answers only; the duplicate-pitch follow-up also lives engine-side for the same reason. The follow-up adds one exception to the rule: it asks for the remaining twin, so tapping the button already credited grades wrong even though it sounds the exact pitch.
